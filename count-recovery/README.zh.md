# 从 T1 RNA 文件恢复整数计数

本文为英文 README 的中文翻译；如有出入，以英文版和官方页面为准。

许多单细胞工具要求输入整数形式的 UMI 计数。scVI 和 scANVI 对计数拟合负二项似然函数；scanpy 的 `seurat_v3` 方法基于计数选择高变基因；使用 DESeq2 或 edgeR 做伪批量（pseudobulk）差异表达分析时，输入的是求和后的计数；泊松重采样也从计数出发。T1 发布数据（E8.5 和 E9.5 的 RNA 文件）在 `.X` 中只保存归一化后的对数值，没有计数层（counts layer）。本工具对每个细胞逆向执行归一化，并检查结果是否全部为整数。

## 术语

- **UMI 计数**：在某一个细胞中，某个基因检测到的唯一分子标识符（UMI，unique molecular identifier）的数量。UMI 是用来标记单个 mRNA 分子的短条形码。它是整数。
- **文库大小**：一个细胞所有基因的 UMI 计数总和。下文记为 L。
- **CP10k**：每万计数（counts per 10,000）。每个计数除以该细胞的文库大小，再乘以 10,000。
- **自然 log1p**：log(1 + x)，使用自然对数。其逆运算为 expm1(y) = exp(y) - 1。
- **AnnData 和 h5ad**：AnnData 是 Python 中存放单细胞数据的容器，h5ad 是它的 HDF5 文件格式。`.X` 保存表达矩阵，`.obs` 每个细胞一行元数据，`.var` 每个基因一行。
- **CSR 和 CSC**：稀疏矩阵（大部分元素为零的矩阵）的两种存储方式。CSR（压缩稀疏行）按行连续存储，CSC（压缩稀疏列）按列连续存储。

## 方法

对于细胞 i 和基因 j，文件中存储的是 x_ij = log(1 + 1e4 c_ij / L_i)，其中 c_ij 为计数，L_i 为该细胞的文库大小。

1. expm1(x_ij) = 1e4 c_ij / L_i。
2. 除以该细胞的最小非零值，得到 c_ij / c_min，其中 c_min 是该细胞中表达量最低的被检测基因的计数。
3. 假设 c_min = 1，即可得到 c_ij，进而 L_i 等于对 j 求和的 c_ij。如果这一假设不能让所有值都为整数，工具会依次尝试 c_min = 2 到 5。整数性就是检验标准。

若数值 s 与最近整数的距离不超过 tol 乘以 max(1, s)，则认为 s 是整数。默认的 tol 为 1.9e-6，即 16 个 float32 机器精度（machine epsilon），足以覆盖 float32 存储带来的舍入误差。此外，每个细胞的计数之和还必须与 L_i 的相对误差在 1e-5 以内。这一检查确认归一化总量等于所存储基因的求和。

归一化后的矩阵无法区分仅相差一个共同整数因子的两个计数向量。因此，需要 c_min 大于 1 的细胞会被记录在 `obs['recovery_smallest_count']` 中，并计入报告。

若要把恢复出的计数转换回发布数据的表示形式，对每个细胞除以其总和，乘以 10,000，再取自然对数 log1p。

## 命令

安装依赖：

```sh
pip install numpy scipy h5py anndata
```

检查文件，但不写出矩阵：

```sh
python vec_counts.py recover input.h5ad --check-only --report check.json
```

恢复计数：

```sh
python vec_counts.py recover input.h5ad counts.h5ad
```

将恢复出的计数与原始 log1p 矩阵进行比较：

```sh
python vec_counts.py roundtrip counts.h5ad input.h5ad
```

在本目录下运行测试：

```sh
python -m pytest -q
```

恢复后的 `.X` 为 int32 格式的 CSR 矩阵，显式存储的零已被去除。`obs` 新增 `library_size`、`recovery_max_residual`（该细胞中归一化值到最近整数的最大距离）和 `recovery_smallest_count`（全零细胞为 0）。`uns['vec_counts']` 记录输入文件名、其 SHA-256 哈希值、容差和工具版本。除非给出 `--force`，否则不会覆盖已有的输出文件和已有的 `obs` 列。若出现 NaN 或 Inf 值、负值、无法恢复整数的细胞，或 CP10k 检查失败，程序会输出提示信息并以非零退出码停止，且不会写出任何矩阵。

## 实测结果

机器：8 GB 内存的 Apple M1 笔记本。版本：anndata 0.13.4、numpy 2.5.3、scipy 1.18.1。

发布的 E9.5 RNA 文件，使用默认容差并加 `--check-only` 运行（2026 年 10 月 8 日）：

| 细胞数 | 基因数 | 恢复成功的细胞数 | 最差归一化残差 | 最小计数大于 1 需要的细胞数 | max abs(sum(counts) - L)（计数之和与 L 的最大绝对误差） | 文库大小 最小 / 中位数 / 最大 | 运行时间 | 峰值内存 |
|---:|---:|---:|---:|---:|---:|---|---:|---:|
| 17,057 | 32,285 | 17,057 | 3.4e-7 | 0 | 0.003 | 731 / 11,080 / 94,591 | 39 s | 1.0 GB |

最差残差约为默认容差的六分之一。该文件包含 6,054,489 个显式零，恢复后的矩阵会去掉这些零。每个细胞的计数之和与其文库大小的相对误差在 1.1e-7 以内，说明该发布数据是在全部 32,285 个基因上归一化的。

发布的 E8.5 RNA 文件（16,787 个细胞）于 2026 年 10 月 3 日用同一方法的早期版本检验：每个细胞都恢复为整数，文库大小从 1,299 到 63,850。写出恢复后的矩阵耗时 25 秒，生成 147 MB 的文件。将这些计数按全部基因计算 CP10k 再取自然 log1p 转换回去后，与原始数值的差异在 2.4e-7 以内，属于 float32 舍入误差。

## 局限

本工具假定 `.X` 中存放的是对所有已存储基因计算的 CP10k 值再取自然 log1p，除此之外没有其他变换。

它恢复的是归一化所编码的计数，而不是经过环境 RNA 或其他质量控制校正后的计数。

CP10k 检查只能确认归一化总量等于所存储基因的求和。它无法发现那些只在部分基因上归一化、之后又只保存这部分基因的矩阵，因为此时所存基因的求和恰好等于总量。T1 文件保存了全部 32,285 个基因，因此对这些文件，该检查确认归一化是在完整基因集上进行的。

在默认容差下，计数超过约 260,000 时无法进行检查，因为舍入会变得不确定。
